# validate-scaffold-staleness

> **Internal primitive** — not surfaced in `capabilities --full`.
> No CLI subcommand and no MCP tool exists to invoke it, so no agent can
> call it directly; `validate-campaign` composes it and escalates any
> error-severity finding to `overall="fail"`. `validate-campaign` is the
> agent-facing verb.

Pre-submit gate that refuses a `.hpc/` scaffold generated by an **older** hpc-agent before it fails with a runtime `ImportError` on a compute node (#364). A scaffold built under a prior version can survive an upgrade and break far downstream — the observed case was a pre-reorg `.hpc/_build_tasks.py` importing `from hpc_agent.template import ...` after `hpc_agent.template` was consolidated away. hpc-agent already version-stamps sidecars / manifests / journal records; this validator closes the same gap for the **generated scaffold**: `build-tasks-py` stamps the generating `hpc_agent.__version__` into `.hpc/.scaffold_meta.json`, and this atom checks that stamp (and the scaffold's imports) against the installed package at submit time — locally, with **no SSH**.

The check is a **no-op when the stamp matches the installed version**: it returns `fresh` without scanning a single import, so a current-version scaffold submits with byte-identical behavior.

## Composers

- **`validate-campaign`** — runs this gate **unconditionally** (it needs no
  spec field, only the experiment dir), because a stale scaffold fails on the
  cluster regardless of which other inputs the caller supplied.

## Contract surface

Takes `experiment_dir` (path, required) — the repo root, and the only input.
There is no `--spec`. The validator reads `<experiment_dir>/.hpc/.scaffold_meta.json`
(the generator stamp) and the generated scaffold files (`tasks.py`, `cli.py`,
and any legacy `_build_tasks.py`).

Returns a `ValidateScaffoldStalenessResult` with:

- `findings` — empty = pass. When stale, a single error finding with
  `code="stale_scaffold"`, a message naming the version mismatch, and a
  `suggested_fix` pointing at regeneration. Its `evidence` carries
  `installed_version`, `stamp_version`, `legacy_artifacts`,
  `unresolved_imports`, and `scanned_files`.
- `status` (`"fresh"` | `"stale"`) — the classification even when there is no
  finding, so a caller can tell "fresh because the stamp matched" from "fresh
  because every import resolved."
- `installed_version` — the installed `hpc_agent.__version__` checked against.
- `stamp_version` — the generator version from `.hpc/.scaffold_meta.json`, or
  `null` for an unstamped (legacy) scaffold.

## Invariants

- **No-op fast path.** When the stamp equals the installed version (and no
  legacy `_build_tasks.py` is present), the validator returns `fresh`
  immediately without scanning any import — guaranteeing a current-version
  scaffold is unaffected.
- **Mismatch alone is not stale.** A stamp from a different version whose
  imports all still resolve against the installed package is **not** refused;
  only a vanished module / removed symbol — or a pre-reorg `_build_tasks.py`
  artifact — flags `stale`. This keeps the gate from false-refusing across
  benign version bumps.
- **Unknown generator → verify, don't refuse.** An unstamped (legacy) scaffold
  is neither silently trusted nor automatically refused: its `hpc_agent.*`
  imports are scanned against the installed package, and it is flagged stale
  only if one no longer resolves.
- **Legacy `_build_tasks.py` is stale by construction.** Current generators
  emit `.hpc/tasks.py`; a pre-reorg `_build_tasks.py` is a dead generated
  artifact and is flagged regardless of whether its imports happen to resolve.
- **Never raises.** A stale or malformed scaffold surfaces through `findings`
  (the validator contract), never as an envelope-level `error_code`.
- **Pure local read** of `<experiment_dir>/.hpc/`. Same on-disk state, same
  result. No SSH, no journal mutation.

## Coupling

- Paired with `build-tasks-py`, which writes the `.scaffold_meta.json` stamp
  this gate reads. A generator that stops stamping silently degrades every
  scaffold to the unstamped import-scan path.
- The scanned file set (`tasks.py`, `cli.py`, `_build_tasks.py`) tracks what
  the generators actually emit; a new generated file is invisible to the gate
  until it is added here.
- `validate-campaign` owns escalation to `overall="fail"`.

## Failure modes

- **Regeneration is the fix, not hand-editing.** The stale file is
  framework-generated, not user source — the `suggested_fix` points at re-running
  onboarding (`hpc-wrap-entry-point` / `interview`) or
  `hpc-agent build-tasks-py --force`, never at editing the superseded file.
- **A scaffold whose imports resolve but whose *semantics* changed** → passes.
  The gate proves importability, not behavioral compatibility.
